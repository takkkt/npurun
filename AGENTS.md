# npurun: notes for AI agents

npurun adds AMD XDNA 2 NPU offload for ternary (`PQ2_0`, `PTQ1_0`) matrix
multiplications to llama.cpp. This repository holds only the integration; llama.cpp
(PrismML's fork) is the submodule `third_party/llama.cpp`, pinned, with
`patches/llama.cpp.patch` applied at configure time. Never commit changes inside
`third_party/llama.cpp`; change the patch instead.

## Where things are

| Path | Role |
|---|---|
| `src/npu/npu.cpp` | ggml CPU "extra buffer type": decides which weights go to the NPU, splits rows NPU/CPU (`GGML_NPU_SPLIT`), groups matrices sharing an input, runs the NPU on a worker thread while CPU threads compute their rows. Compiled into llama.cpp's `ggml-cpu` target by `cmake/npu-backend.cmake` |
| `src/npu/npurun.cpp`, `npurun.h` | XRT host runtime: weight packing (base-3, 1.75 bit/weight), activation quantization, launch planning (fused / K-sliced / 4-token batch), result reduction |
| `src/npu/tgemv.xclbin`, `gen/*.inc` | Prebuilt NPU core program and DMA instruction builders. Generated by `kernel/npurun/build_dyn.py`; never edit by hand |
| `kernel/tgemv.cc` | The AI Engine kernel (C++ with aie_api) |
| `kernel/npurun/*.py` | IRON designs, packing reference, NumPy emulator |
| `patches/llama.cpp.patch` | Hooks: register the NPU buffer type in ggml-cpu, export two repack helpers, default `n_rs_seq = 1` (in-place recurrent state for qwen35) |
| `tools/` | `npurun-test`, `npurun-bw` |

## Build and test

Windows, "x64 Native Tools Command Prompt for VS 2022":

```bat
cmake --preset release
cmake --build build -j
```

Verification after changing NPU code (needs the NPU):

1. Kernel/runtime correctness for any shape: `build\bin\npurun-test src\npu\tgemv.xclbin <K> <M0,M1,..> <iters> <tokens>`; every line must report worst cosine > 0.999.
2. End-to-end quality: `llama-perplexity -m <ternary 8B gguf> -f <text> -c 128 --chunks 3` with `GGML_NPU=0` vs default; the estimates must agree within the error bar.
3. Speed: `llama-bench -m <model> -p 64 -n 16 -t 6 -mmp 0 --poll 100` and compare with `GGML_NPU=0` in the same session (background load makes single runs unreliable).

Changing the NPU kernel (`kernel/`) requires the IRON toolchain; see `kernel/README.md`,
then run `python -m npurun.build_dyn` from `kernel/` and commit the regenerated
`tgemv.xclbin` and `gen/*.inc` together with the source change.

## Updating llama.cpp

1. `git -C third_party/llama.cpp checkout -- . && git -C third_party/llama.cpp fetch && git -C third_party/llama.cpp checkout <new commit>`
2. Configure; if the patch no longer applies, port the hooks by hand, then regenerate it with
   `git -C third_party/llama.cpp diff > patches/llama.cpp.patch`.
3. Rebuild, run the verification above, commit the submodule bump and the patch together.

## Invariants

- The NPU program is shape-agnostic; matrix shapes live only in the per-call instruction streams. Keep `design.py` and `design_dyn.py` identical in cores/fifos/object sizes.
- Output must stay equal to the CPU path within quantization noise; do not trade accuracy for speed without an explicit opt-in flag.
- Anything the NPU cannot run must fall back to the CPU silently (`supports_op` false), never abort.
- `GGML_NPU=0` must give exactly the llama.cpp CPU behaviour. The NPU is opened only when a model has ternary weights.
- Keep the llama.cpp patch minimal; new logic goes in `src/npu/`.
