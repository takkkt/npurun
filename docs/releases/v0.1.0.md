First public release of **npurun**: llama.cpp for the AMD Ryzen AI NPU.

Ternary (1.58-bit) GGUF models such as PrismML's Ternary Bonsai run on the XDNA 2 NPU
together with the CPU. Every other GGUF model runs on the CPU exactly as in llama.cpp.

### Download and run

1. Download `npurun-v0.1.0-win-x64.zip` below and unzip it.
2. `hf download prism-ml/Ternary-Bonsai-2-27B-gguf Ternary-Bonsai-2-27B-PQ2_0.gguf --local-dir models`
3. `npurun-chat.cmd models\Ternary-Bonsai-2-27B-PQ2_0.gguf` or `npurun-server.cmd ...` (web UI + OpenAI API at http://127.0.0.1:8080)

**Needs:** Windows 11 x64, Ryzen AI 300 / 400 / Max (XDNA 2 NPU), the AMD NPU driver (AMD Software / Adrenalin). 16 GB RAM for the 27B model, 32 GB recommended.

### Performance (Bonsai 2 27B, Ryzen AI 9 465, 32 GB)

| | CPU only | npurun (NPU + CPU) |
|---|---|---|
| Generation | 3.3 – 3.9 tok/s | **4.1 – 5.2 tok/s** |
| Prompt processing | 10.1 tok/s | **12.2 – 13.8 tok/s** |

### What's in it

- NPU offload for `PQ2_0` and `PTQ1_0` weights: rows split 75/25 between NPU and CPU, fused q/k/v and gate/up launches, 4-token batches for prompts, any layer width (padding and K slicing).
- Output identical / perplexity equal to the CPU path.
- One embedded NPU program; no AMD compiler toolchain needed to build or run.
- All llama.cpp tools: `llama-cli`, `llama-server`, `llama-bench`, `llama-perplexity`, ...

### Known limits

- Windows only for now.
- Non-ternary models (Q4_K_M, Q8_0, ...) run on the CPU; on this hardware the CPU already uses most of the memory bandwidth for them.
- On small ternary models (8B and below) the CPU alone can be as fast as NPU + CPU for generation.
